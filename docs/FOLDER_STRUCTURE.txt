# ANDRIL Flutter — Physical folder structure v1.1

The V1.1 blueprint expands the verified 123-directory optimized scaffold. That scaffold contained 123 files, including 99 zero-byte markers and 24 substantive files. The tree below reflects the expanded filesystem.

## Clean Architecture and MVVM

- Application composition belongs in lib/app. Use one router with feature route registrations and guards. Keep shared theme primitives and the Learning, Hobbies and Social theme boundaries.
- lib/core owns reusable infrastructure. It has no dependency on product implementations. lib/shared_core owns account workflows. lib/features/common owns module-scoped shared features, including Diary.
- Learning, Hobbies and Social are the three product modules. Each owns its private profile data, screens, state and business behavior. Use backend-authorized module-profile scope for caches, requests, drafts and subscriptions.
- Screens and widgets render state from ViewModels. Domain defines business types, policies and repository interfaces. Data implements those interfaces and maps external DTOs. App composition wires dependencies.
- Groups, Andril Map and Personality each use one data/domain/presentation tree. Preserve module-specific group contracts. Social Home and Profile should share one Personality destination. Its v1 questionnaire is optional and requires 12 valid answers for completion.
- Social requires backend-confirmed 18+ eligibility and explicit opt-in. Match-based private communication requires server-authorized mutual matching. MoodTone stays Social-only.
- Andril Map reserves a Mapbox boundary, fresh in-app capture and location evidence. Public visibility and rewards depend on server and Admin approval. Flight Points, module XP and purchased coins remain distinct. Excluded Hobbies events and removed Learning features stay out of scope.

## Assets, tests and implementation status

- The official branding PNG is the existing asset. Icons, images, illustrations and animations are organized by Shared Core, Common and the three product modules. Gifts and fonts have dedicated placeholder paths.
- test includes the existing app widget test and placeholder coverage for app infrastructure and scoped features. integration_test reserves onboarding, module isolation and module journeys.
- Read the tree labels as [files] for a directory that contains substantive files somewhere below it, [scaffold] for a placeholder-only subtree, [existing file] for a preserved substantive file, and [structure document] for this updated file.
- [v1.1] marks a directory or marker added relative to the verified 123-directory scaffold. Existing markers were retained. New markers belong only to empty leaves.
- This is a filesystem scaffold. Add product code, contracts and dependencies through separate implementation work. Preserve authorized scope and do not add mock files that imply feature completion.
- Existing localization resource lib/l10n/app_en.arb is preserved. app_ta.arb and app_si.arb remain pending genuine translations. The official Tamil name is அன்றில்.
- Android still requires an approved application ID, toolchain and platform generation. Flutter packages, generation, builds and tests were outside the scope of this migration.
